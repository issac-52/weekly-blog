# 출처 관리 업데이트 v2.2

현재 master 기준: `3b98928327ebd31fcaa8bf04cbe765fde4739854`.
GitHub push·운영 배포·사용자 Supabase·기존 예약 설정은 변경하지 않았습니다.

## 적용 순서

1. 로컬 수정은 커밋하거나 보관하고 master를 최신화한 뒤 새 브랜치를 만듭니다.
2. 동봉한 `browinfo-source-management.patch`를 `git am`으로 적용합니다. 기준 이후 다른 수정이 있으면 충돌을 검토합니다. 실패 시 `git am --abort`로 취소할 수 있습니다.
3. **새 Browinfo 전용 Supabase** SQL Editor에서 `202610280004_source_registry.sql`만 한 번 실행합니다. 기존 001~003이나 optional OAuth SQL은 다시 실행하지 않습니다. migration은 기사·Auth·통계·OAuth를 수정하지 않습니다. 앱 새 버전보다 SQL을 먼저 적용하세요.
4. `npx pnpm install --frozen-lockfile`, `npx pnpm run build`로 확인합니다. 신규 패키지는 추가하지 않았고 기존 Vercel Analytics 의존성을 유지했습니다.
5. 승인한 코드만 master에 병합·push하여 Vercel에 배포합니다. 기존 Git 연결에서 push는 자동 배포를 일으킬 수 있습니다. DNS·OAuth 환경변수는 변경할 필요가 없습니다.
6. `/admin/sources`에 로그인해 도메인 추가·수정·비활성화를 확인합니다. ChatGPT 플러그인의 도구 목록을 새로고침해 변경된 제출 스키마와 출처 정책을 읽도록 합니다. 새 OAuth 앱을 만들 필요는 없습니다.
7. ChatGPT에서 `get_draft_context`를 읽으면 출처 정책이 포함됩니다. 새 도메인의 실제 원문으로 테스트 초안 하나를 제출한 뒤 관리자 화면에서 편집 확인을 저장하고 승인합니다.

## 매체 추가

- 관리자 화면의 **출처 관리** 링크를 엽니다.
- 기사 URL이 아닌 실제 도메인(예: `news.example.com`)을 등록합니다. 이 예시 주소는 실제 출처가 아닙니다.
- 매체명, 유형(공식/뉴스/연구/기타), 사용 허용, 이용 조건 메모를 저장합니다.
- 기본은 정확한 호스트만 허용합니다. `example.com`만 등록하면 `www.example.com`은 포함되지 않습니다. 하위 도메인도 필요하면 체크하거나 정확한 호스트를 별도로 등록합니다. 가장 구체적인 등록이 우선합니다.
- 저장하면 다음 초안 제출·접근 검사·승인·발행 때 반영됩니다. 익명·일반 사용자는 설정과 감사 이력을 읽거나 쓸 수 없습니다.
- 기존 13개 공식 도메인과 `developers.openai.com`, `supabase.com`을 기본값으로 추가했습니다. 신문사 도메인은 편집자가 이용 조건을 확인한 뒤 등록합니다.
- 목록은 최대 200개, 기사당 출처는 최대 8개입니다. 보통 관련 출처 2~4개를 권장하며 동일 보도자료의 전재를 독립된 근거로 세지 않습니다.

## 접근 검사와 내용 검토

자동 검사는 허용 도메인의 공개 HTTPS 텍스트에 접근할 수 있는지를 확인합니다. 사실의 진위, 유료 기사 전문 열람, 재사용 권리를 판정하지 않습니다. DNS와 리디렉션의 내부 주소 접근도 차단합니다. 도메인을 등록해도 로그인·유료벽·봇 차단을 우회하지 않습니다.

자동 접근 실패 시 편집자가 합법적으로 원문을 읽었다면 출처 카드에 열람 방법과 대조 내용을 20자 이상 남겨 수동 확인할 수 있습니다. 원문을 보지 못했다면 수동 확인하지 말고 다른 출처를 사용하거나 검토를 보류합니다. 수동 확인은 자동 접근 성공 표시로 바뀌지 않으며, 확인 기록과 작성자는 비공개 기사 변경 이력에 저장됩니다. 비활성·미등록 출처는 수동 확인으로 우회할 수 없습니다.

승인은 `내용 저장 → 출처 검사 또는 필요한 수동 확인 → 편집 확인 4개 체크 → 수정·검토 저장 → 검토 승인 → 발행` 순서입니다. 본문 수정·출처 재검사·수동 확인 변경은 편집 확인과 승인을 초기화합니다. 저장하지 않은 항목이 있으면 안내를 표시하고 승인을 막습니다.

네 번째 편집 확인은 인용·사진·표·이용 조건 확인입니다. 기존 기사는 이 값이 없으므로 다음 승인·발행 때 직접 확인해야 합니다. 이미 공개된 글은 자동으로 내리지 않지만 해당 글을 수정하면 다시 검토하게 됩니다. 도메인 비활성화 역시 기존 공개 글을 자동으로 삭제하지 않습니다.

## 저작권을 고려한 편집 원칙

출처 등록·링크 표시·AI 작성 고지는 이용 허락을 대신하지 않습니다. 사실을 여러 원문에서 대조해 직접 해설하고, 필요한 최소 인용은 인용 부분·매체·날짜·원문 URL을 명확히 표시합니다. 기사의 특유한 문장과 전개를 따라 요약·번역하거나 전문·사진·그래픽·표를 복제하지 않습니다. 특정 매체 콘텐츠를 반복적으로 대량 요약해 원문 이용을 대체하는 운영은 이용허락이나 라이선스 필요성을 검토해야 합니다. 유료벽을 우회하지 않으며 공개 기사에도 매체별 이용 조건을 확인합니다. 이 항목과 체크박스는 저작권 적법성의 자동 판정·보장이 아닙니다.

## 운영 메모

출처 설정과 출처 변경 감사 이력은 별도 테이블 두 개입니다. 기존 콘텐츠 JSON 내보내기는 기사의 수동 확인 변경 이력은 포함하지만 출처 관리 테이블 전체 백업은 포함하지 않습니다. 출처 목록·설정 이력의 복구에는 Supabase DB 백업을 사용하세요.

적용 중 문제면 이전 배포로 되돌릴 수 있습니다. 새 테이블은 남겨두어도 이전 코드에 영향을 주지 않습니다. 테이블이나 기존 SQL을 삭제하는 복구는 필요하지 않습니다.
