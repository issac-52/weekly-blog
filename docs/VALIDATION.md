# 검증 결과 (2026-10-28, v2.2)

## 로컬 검증

- Next.js 프로덕션 빌드, TypeScript 검사.
- Node 테스트 15개: 출처·승인·발행 품질 검사, 관리자 이메일, 한국 ISO 주 경계, PostgreSQL 콘텐츠/RLS/원자적 RPC, 통계, 실제 서명 JWT 검증, MCP SDK 호출, OAuth hook.
- PGlite에서 migration 001~004과 선택 OAuth hook 실제 적용. 통계는 KST 날짜, 중복 이벤트, 발행본만 집계, 방문 브라우저 수, 추이 빈 날짜, 인기 글, RLS 접근 거부를 확인했습니다.
- 실제 ES256 서명 토큰의 client_id·관리자 UUID·scope·issuer·audience·만료 검증. MCP는 초안 컨텍스트/제출/상태 3개 도구만 노출하며 승인·발행 도구는 없습니다. hook은 지정 client와 관리자에만 초안 권한을 추가하고 DB role을 높이지 않습니다.
- 실제 빌드 서버 HTTP 검사: 비공개 Basic Auth, 관리자 페이지 이동·관리 API 익명 거부, OAuth MCP/ingest의 인증 challenge, metadata discovery, 통계 비활성·교차 Origin 거부, 제거한 유료 생성/Cron 경로 404.

## 운영 환경에서 추가 확인할 부분

- 새 Supabase에 실제 SQL·백업 적용, 이메일/비밀번호 로그인, 세션 갱신.
- 배포 주소에서 Supabase OAuth 동의·토큰 갱신·ChatGPT 도구 연결 및 실제 예약 실행. 로컬 MCP 프로토콜 검증은 외부 연결 성공을 뜻하지 않습니다.
- 승인 후 공개 전환 시 실제 브라우저 조회→관리자 통계 반영. 비공개 상태와 관리자 방문은 수집하지 않으며 이전 방문은 소급 집계되지 않습니다.
- 사용자 Vercel 배포와 실행 시간 한도·도메인 연결.

현재 결과는 검증한 이전 코드이며 사용자 서비스에 적용 완료한 상태가 아닙니다. 별도 유료 LLM API·Vercel 생성 Cron은 제거했습니다. 외부 계정·예약·사이트 설정을 변경하지 않았습니다.

## v2.2 출처 관리 추가 검증

- 도메인 정규화, HTTPS와 정확한 호스트/하위 도메인 범위, 구체적인 비활성 규칙 우선 적용.
- 요청 전 DNS 결과의 사설·루프백·링크로컬·특수 주소 차단, 검증된 주소로 TLS 연결을 고정하는 구조. 테스트에서는 DNS와 전송을 대체해 차단 대상에 요청하지 않는지, 리디렉션마다 다시 검사하는지 확인했습니다.
- 공개 HTTPS 원문은 텍스트 크기·시간 제한을 두고 검사하며 접근 차단을 우회하지 않습니다. 자동 성공도 전문 열람이나 이용 허락을 뜻하지 않습니다.
- 실제 PostgreSQL 출처 테이블/RLS/서비스 전용 변경 RPC, 이전 버전 거부, 설정과 감사 이력의 원자적 저장, 200개 한도.
- 수동 원문 확인으로 자동 reachable 값은 바꾸지 않으며 비활성 출처 우회 불가. 확인자·메모는 비공개 기사 변경 이력에 저장하고 공개 기사에는 기록 ID·시각만 둡니다.
- 권리 확인이 빠진 승인·발행 거부. 새 관리 페이지/API의 익명 접근 거부.
- 운영 DB의 004 적용, 실제 관리자 도메인 추가·비활성화, 로그인 상태에서 수동 확인 UI, 갱신된 MCP 도구 스키마는 사용자 배포 후 추가 확인해야 합니다.

외부 HTTPS 원문을 새 네트워크 경로로 직접 확인하려 했으나 실행 환경의 DNS 조회가 EAI_AGAIN으로 실패했습니다. 위 네트워크 검증은 대체 DNS/전송으로 수행한 차단·리디렉션 테스트이며 실제 Vercel에서 각 매체의 접근 가능성을 보증하지 않습니다.
